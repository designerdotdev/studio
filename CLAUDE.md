# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Designer Studio is a Laravel package (not a standalone app) that provides a visual page builder for Laravel applications. **The site it edits is a set of ordinary files in the host app** — a DevDojo site-template installed into `resources/designer` + `public/designer` and served by `app/Providers/DesignerServiceProvider.php`, a runtime Studio writes into the app that has no dependency on the package (remove Studio and the site keeps working). Studio itself keeps JSON documents (no database) as its working model — a mirror of those files plus a draft — and uses Livewire 3 for the editor panel and an iframe canvas rendered server-side. The host app for local development is the Laravel app that contains this package at `packages/designer/studio` (three levels up), which path-symlinks it via composer.

## Build Commands

```bash
npm run build          # Build frontend assets (Vite → dist/)
npm run dev            # Watch mode: builds Monaco once, then rebuilds dist/ on every change (re-publishing to the host's public/vendor/studio if published assets exist)
```

There are no tests or linting configured in this package. Verify changes against the host app (`php artisan serve` from the repo root, then hit `/studio`).

## Architecture

### Package Structure

- **Namespace**: `Designer\Studio` (PSR-4 from `src/`)
- **Service Provider**: `StudioServiceProvider` — singletons, editor routes, views, Livewire components, `@studioStyles`/`@studioScripts` directives, the site's components path for canvas renders, and a `terminating` flush of live documents to files (draft mode off). It registers **no public routes** — the installed runtime serves the site
- **Config**: `config/studio.php` — route prefix, middleware, optional `gate`, `draft_mode`, `dev_mode`, storage path, iframe CDN options, and `templates` (clone cache path + the catalog: 10 templates, each with a `category` — starter, landing or business — that the onboarding picker filters on)
- **Hardening**: every route has parameter constraints (`[a-z0-9-]+` slugs/names); upload (30/min), publish/discard (12/min) are throttled; `StudioController::editorNotices()` surfaces unprotected-in-production, unwritable-storage, app-owns-root and blocked-template-link states as toasts that stay until closed (`home.blade.php` raises them on `studio:revealed`; closing a `dismissible` one is remembered in `studio.notice.<id>`); the editor shows a small-screen overlay below `lg`
- **Concurrent edits**: `EditorPanel::$docVersions` tracks page/layout `updated_at` at load; `guardConflict()` blocks every mutation with a Reload toast if the doc changed elsewhere (block-content edits skip the guard — blocks are shared by design)
- **The installed site** (`Support/SitePaths` is the single source for its locations): `resources/designer/{designer.json, css, data/site.json, data/collections/*.json(+yml), views/pages, views/components/{sections,layouts,blocks,…}}` and `public/designer/{images,js,…,uploads}`. `designer.json` (`Services/Site/SiteManifest`) holds what a page file can't: page titles/description/order/meta (SEO)/previous_slugs, home slug, layout and block names — the runtime reads it for SEO tags and renamed-page 301s
- **The runtime** (`stubs/DesignerServiceProvider.php.stub` → `app/Providers/DesignerServiceProvider.php`, written + registered by `Services/Site/RuntimeInstaller` via `ServiceProvider::addProviderToBootstrapFile`, self-healed on editor load, never overwritten once it exists): registers the components path, serves from `Route::fallback` (app routes always win, `route:cache`-safe): pages (`/` → `index`, flat file beats `dir/index`), `[collection.field]` dynamic pages (row shadows the collection, `$entries` = all rows), `/sitemap.xml`, home-slug and `previous_slugs` 301s, the site's `404.blade.php`; shares `$site`/collections/markdown content as objects; swaps Vite for a static projection of `resources/designer/*` entries (Tailwind browser CDN + inlined `<style type="text/tailwindcss">`, other entries go to the app's Vite); injects per-page SEO tags the layout doesn't write. Mirrors Pocketknife's Laravel runtime (`~/devdojo/pocketknife/laravel`) + DevDojo's DynamicPages
- **Claiming `/`**: `Support/WelcomeRoutePruner` auto-removes the stock Laravel welcome route from the host's `routes/web.php` (strict regex — customized routes are never touched) so the home page serves at `/`. Runs on install, on publish (`home_claimed` → toast), and on editor load; requires `views/pages/index.blade.php`; clears the route cache when needed. `Support/SiteUrls::pageUrl()` is the single source for public page URLs; `ownsRoot()` = the app has no GET `/` of its own (then the home page is served at `/{home_slug}` and the editor shows an `app-owns-root` notice)
- **Developer mode is one switch with two editors behind it.** `$store.studio.developer` (= the server gate `DevMode::enabled()` AND the menu's **Developer mode** switch, localStorage `studio.devmode`, **off until someone turns it on** — only the value `'1'` counts as on, in `home.blade.php` and in the canvas's boot in `studio.js` alike) is THE gate for chrome; the canvas mirrors it as `html.studio-devmode`. On: the Code view, the Assistant (the top bar's button, in the right column; `chatAvailable` is `developer`, and turning the switch off closes it and leaves the Code view), the toolbar's Ask AI, edit-code buttons, source lines + ⌥-click + promote-a-field on the canvas, code bindings ("Set in code"), Unlink/Unbind/"Bind to a collection…", collection schemas + New collection, layouts (create/rename/delete — assigning one stays for everyone), a page's JSON-LD + custom head HTML. Off: the editor a marketing team uses — sections and their fields, pages, content rows, media, page settings, Publish — with nothing that reads as code; a code-bound field is not listed at all, matching the canvas (no affordance). Where the server gate is off there is no switch and the editor is always the second one. **Gate new developer-only chrome on `$store.studio.developer` (views) or `html.studio-devmode` (canvas), never on the server gate alone**
- **Dev mode**: `Support/DevMode::enabled()` — `config('studio.dev_mode')` (env `STUDIO_DEV_MODE`), default null = local environment only. When on (server gate + `$store.studio.devMode` toggle in the hamburger menu), the inspector header shows an Edit-code button that opens a Monaco modal (Blade/YAML tabs; the JSON keys stay `html`/`yaml`) for the selected section's `.blade.php` + `.yml` (`DesignSyncService::sourceFiles`). `DevModeController` (`GET|PUT /studio/api/dev/components/{name}`) validates the YAML, writes both files in place (contents from the raw body — TrimStrings), runs `SiteMirror::sync()`; the frontend then refreshes the preview and dispatches `studio:code-saved` (EditorPanel re-syncs and reloads fields). The modal's Save is a split button (`.s-split` in `studio.css`: the action, and a chevron that opens a dark menu rising from it) — Save (⌘S) stays the default, Save and close (⇧⌘S) is in the menu; a failed save keeps the modal open
- **One mode (the focused editor, 2026-09-26 — `docs/superpowers/specs/2026-09-26-focused-editor-design.md`).** The page is always editable; there is no Preview / Edit control (Preview is the open-in-new-tab link). What the stage holds is the **view** (below): `$store.studio.mode` is now a getter over it — `code` in the Code view, `edit` otherwise — still mirrored to `localStorage['studio.mode']` for the canvas's boot; a saved `preview` falls back to `edit`. The editor sends `studio:mode` to the iframe, which also reads it from localStorage at boot. The iframe still understands `html.studio-preview` (chrome hidden, `Studio.preview.select/addAt` refuse, links post `studio:navigate` → `StudioEditor.navigate()`), nothing sends it any more
- **The page is the list.** There is no Sections panel: every section carries its own chrome on hover — the name chip (top-left, a scope-coloured dot: blue page, violet layout, teal global block) and the **toolbar** (top-right, one dark glass bar): `···` (Make global · Duplicate · Hide/Show · Edit code [dev] · Delete, a `studio-menu` anchored under the button via `moreMenu()`), `↑` `↓` (each rendered only where there is somewhere to go — `docFirst`/`docLast`), `✦ Ask AI` (dev mode; a menu — `aiMenu()`: **Ask…** is `askAi()` → `studio:ask-ai` → `$store.studio.askAi(id)`: selects the section, opens the Assistant tab, focuses the composer; the section is the composer's context chip, read reactively from `$wire.selected`. **Improve** (`studio:ai-improve` → `improveSection`) and **Variations…** (`studio:ai-variations` → `designVariations`, offered only where `ImageVariations::sectionsAvailable()`) are described under *Section variations* below), and **Edit** (filled in the scope colour; reads **Done** while that section is being edited). A section under 72px (a nav bar) centres its chip and toolbar on its own height (`is-short` + `--studio-h`, measured on mouseover) — they sit on the section they belong to, never hung over the next one. **Add section** is a pill on the bottom edge of the hovered/selected section (`studio-insert--bottom`, pointer-events only while shown; a layout/page boundary offers both targets) plus a quiet 22px band on the first section's top edge. Shortcuts on a selected section: `E` edit, `A` ask, `⌘D`, `⌘↑/↓`, `⌫`, `Esc`. **A selection lasts while the pointer is on its section**: a click selects (the 2px outline, and the section the shortcuts act on), and leaving the section lets go (`StudioPreview.pointerLeft` → `releaseSelection()` → `studio:selection-released`). The state that stays is Edit. A menu opened for the section holds the selection until it closes; a selection the editor made (`studio:select` — a moved section after the reload, `A`) stays until the pointer has been on it and left. The release clears the canvas and `StudioEditor.selectedId` only — Livewire is not told, so the Assistant's context chip survives the walk to the composer
- **Editing is a slide-over.** `$store.studio.inspector` is `null | 'section' | 'page'`: the right column (`aside.s-inspector`, the `inspector` slot, 300–560px, localStorage `studio.inspector-width`) holds `EditorPanel`, which renders the selected section's fields or page settings — never a list. `openInspector(id)` (Edit, `E`, the context menu, `studio:open-inspector`) moves to the Design view, brings the fields to the front of the right column (`front = 'inspector'` — an open Assistant waits behind them), sends `studio:focus {sectionId, on}` and the canvas **isolates** that section (`html.studio-focus`, `.is-editing`): every other section, region and add pill leaves the layout and the edited one becomes a card on a dotted canvas — its own page background inside (`--studio-site-bg`, read from the body by `setFocus()`), the same 32px of canvas on every side (`--studio-focus-gap`), the rail turned into **a bar across the top of the canvas** (`position: fixed`, `--studio-bar-h` 56px, a frosted strip of the canvas's grey that the card scrolls under, carrying the chip and the toolbar, ↑↓ hidden; it takes the pointer, so a click on it does not end the edit), a caption under the card. The card itself must have no `overflow` and nothing that transforms it — either captures the fixed bar inside the card — so the rounded clip is on `[data-section-content]` and the entrance animates `top` and `opacity`; a section that holds a `header`, a `nav` or anything `aria-expanded="true"` swaps that clip for a `clip-path: shape()` of the card's rounded rectangle plus everything below its bottom edge, so a dropdown or mega panel hangs over the canvas instead of being cut off at the card (every other section still stops at the card); the scroll position is saved on entry and restored on exit (instant scrolls — sites set `scroll-behavior: smooth`). Done, Esc, the panel's × or a click on the canvas around the card (`studio:focus-exit`) calls `closeInspector()`: the page comes back and the section is deselected, and an Assistant that was open behind the fields shows again. `openPageSettings()` is the same column with the page left as it is (⌘,, the switcher's gear, the menu, New layout…)
- **Code mode**: `Services/CodeWorkspace` is the single authority for which files exist and how a browser path becomes a real one. Paths are real paths relative to the app root, and the tree is **the whole application** — hidden files included (`.env` too) — **one folder per request** (`tree?dir=…`; a folder not yet fetched is `lazy`, and `$store.code.expandOpen()` refetches the open ones on reload), with the site's folders tinted via each node's `design` flag (a first visit opens on `resources/designer`). The root request also carries `index`, every text file of the site (`siteFiles()`), which is what the palette's quick-open searches — the tree itself only knows the folders that have been opened. Everything is listed, but `inert` nodes never open (`note` says why): `INERT_DIRS` (`vendor node_modules .git`, never descended), binary files (`BINARY_EXTENSIONS` or a NUL in the first 8 KB), files over 512 KB. Every path is realpath-checked against the app root; `..` and any `INERT_DIRS` segment rejected; 4000-node walk cap. Because the tree can open `.env`, dev mode must stay off anywhere it isn't yours. While the split's seam is dragged, an `s-drag-shield` covers the window so the preview iframe can't swallow the mouse events. Saves under the site validate YAML/JSON first. `CodeController` (`/studio/api/code/{tree,file,duplicate,section}`, 404 unless dev mode) reads and writes files and **makes, renames, duplicates and deletes files and folders** (`POST|PATCH|DELETE code/file`, `POST code/duplicate` → `CodeWorkspace::create/rename/duplicate/delete`); any write under the site runs `SiteMirror::sync()` and returns `synced: true`, and the frontend then dispatches `studio:code-saved`. A section is a pair: renaming, duplicating or deleting either half does the same to the other. What must not move is refused on the server and not offered in the tree: dependency trees, top-level project folders, the folders the site lives in (`resolveMovable()`, `$store.code.locked()`), a folder holding more than 500 files. "New section" scaffolds `views/components/sections/<name>.blade.php` + `.yml`. **The tree** (`partials/file-tree.blade.php`): a header with the project's name and New file · New folder · Refresh · Collapse all · Hide; a new file or folder is named in a row of its own inside the selected folder (`$store.code.draft`), a rename edits the row in place (`renaming`; open buffers follow the path with their unsaved edits — `remap()`), Delete is two clicks inside the row (`confirmDelete`); a right-click opens the dark context menu (teleported to `<body>`: New file… / New folder… / New section… inside the site · Rename… F2 · Duplicate · Copy path · Copy relative path · Refresh · Delete… ⌘⌫ — a locked folder and an inert row offer only what applies), and the rows take the keyboard (↑ ↓ Home End, ← → fold and open, F2, ⌘⌫, the menu key). The file in the editor is always the row lit in the tree: `activate()` opens its folders and scrolls its row into view (`showInTree()`), however it was opened. The UI: `$store.code` holds the flat tree (`partials/file-tree.blade.php`, rendered from `CodeWorkspace::tree()`'s depth/parent list — no recursion), which is **docked inside the stage beside the editor** (`.s-dock.s-code-files` in `home.blade.php`, `$store.studio.docks.code`, folded by ⌘B or its header button, width `studio.dock-width`). The Code view is one surface: the files, the tab strip and Monaco share `--color-code` (Monaco's own background — `#0b0b0d` dark, white light), the files' header and the tab strip are both 40px so one hairline crosses the view, and the right column beside it drops `.s-light` so the Assistant follows the editor's theme too. The pane's empty state offers **Show the files** when they are folded away. `partials/code-pane.blade.php` is tabs over one Monaco instance with a model per file (undo history survives tab switches); the split toggle sits in the tab strip. Monaco loads on the first file open, not on entering the Code view. A file edited and not saved lives only in the window, so a `beforeunload` guard asks before a reload or a page switch throws it away (closing a tab keeps its buffer). `codeSplit`/`codeSize` (localStorage `studio.code-split`/`studio.code-size`) put the live preview beside the editor behind a drag seam
- **The view decides the stage, and each view owns its left side (the shell, 2026-10-01).** `$store.studio.view` is `design | content | code` (localStorage `studio.view`), set by the top bar's switch (`setView()`); `stage` (`page | content | code`), `mode` and `canvasVisible` are getters over it. **Design**: the canvas, with the **rail** on the frame beside it (`partials/rail.blade.php`: Add section, Pages, Media, and at the foot Page settings and ⌘K). Pages and Media open as a **flyout** — `aside.s-flyout`, the rail opening out over the stage's left edge: flush with the top bar and the rail and in the frame's own colour (near-black, or the light theme's grey — it follows the theme like they do), with a hairline and a soft shadow on its one free edge, and the frame curving inward by `--studio-radius` where that edge meets the top and bottom of the stage (`::before`/`::after`), so the canvas beside it still reads as a rounded card, `$store.studio.drawer` (`null | 'pages' | 'media'`; `openDrawer`/`closeDrawer`/`toggleDrawer`, `drawerShown` is what stays drawn while it slides away) — and nothing is pushed aside. Opening one puts the caret in its search field. It closes on its ×, Esc, the rail button, a view change, or **any press on the canvas** (the iframe posts `studio:canvas-down`). Media is also the image picker from any view (`Studio.mediaPick()` opens the flyout — above Content's entry drawer — and puts back whatever the flyout held). **Content**: `.s-content.s-light`, the collections docked on the left (`ContentPanel` in a `.s-dock`) and the table beside them. **Code**: the files docked beside the editor (above). The docks fold with ⌘B (`toggleSide()`: Design's last flyout, otherwise the view's dock). Leaving Design closes the inspector; anything that needs the page calls `setView('design')` (`leaveContent()` is kept for the page switcher and the palette). **A light surface is whatever carries `.s-light`** — the token retune and every light-chrome rule key on that one class (`:is(html.studio-light, .s-light) …`), never on a component's own class
- **Command palette**: ⌘K opens it ("Add section…" is its first entry, and every other page is a "Go to …" row). Alpine-only, defined in `home.blade.php`; commands are filtered by a `when` flag so mode/panel entries only appear where they apply, and in the Code view the workspace's files join the list as quick-open. It lists what people do — sections, pages, the views, the panels, Publish, widths, appearance, developer mode — and nothing about arranging the chrome
- **Inline editing on the canvas — switched off** (`StudioPreview.inline = false`; the focused editor edits a section in the inspector, and hovering a section shows only its outline and toolbar). The machinery stays behind that flag and `studio:inline:verify` still guards the sentinels; what follows describes it as built: hover a heading and the canvas names the field behind it; click it and you type into the page. Nothing is annotated — a canvas-only pre-pass (`Services/Inline/{EchoScanner,Instrumenter,EchoRef}`) weaves HTML comment sentinels (`<!--sf:headingStart@41-->`, `data-sf-attr`, `data-sf-when`) around every echo of a declared yml field, and `StudioFields` (in `studio.js`, iframe-side) walks them into live `Range`s. `SectionRenderer`'s `$instrument` flag defaults **off**; only `StudioController::iframe()` and `RenderController` turn it on, so no sentinel reaches the draft preview, a thumbnail, or a page file. `StudioPreview.editabilityOf(entry, sectionId)` → `edit|select|code` is **the** gate every affordance must consult (a `collections.*`/`php:`-bound field is never canvas-editable — `saveVariables()` discards writes to bound keys). **Only yml-declared fields get an affordance**: `code` paints nothing (no grey halo, no chip, no badge — the native cursor is the tell), and a `collections.*`-bound list is ONE target — every row outlined together, chip `Digest · 3 rows` — and the click opens the **collection card** in place beside it (`StudioPreview.collection`: rows as an accordion, the clicked one unfolded, typing saves through `CollectionController` and the page follows; add / move / delete with Undo); the inspector's bound-repeater card in `fields/repeater.blade.php` still lists and edits the same rows. The type badge **is** the cursor over an editable field (`#studio-cursor`, a circle with one square corner at the pointer; `html.studio-cursor-on` hides the native cursor over section content). The overlay has exactly one writer: `paintHalo` (read) → `queuePaint` → `flushPaint`. Text commits on blur through `EditorPanel::setFieldFromCanvas`, which deliberately does NOT echo back to the iframe (that would repaint over the caret): 0 requests while typing, 1 Livewire round trip on blur. ⌥-click a field in dev mode to open Code mode at the exact source line. **Read `docs/inline-editing.md` before touching any of it**
- **Dependencies**: livewire/livewire, symfony/yaml, symfony/process (git, for template sync) — no Filament, no Katana
- **Site templates**: whole starter sites in their own git repos (the Designer template repository format, `github.com/designer-templates/<slug>`); the catalog offers two starting points — Blank (chrome only, an empty home page) and Starter (a neutral kit of sections over four pages) — and eight landing pages: Aisle, Ascent, Bramble, Canary, Pacer, Pinnacle, Pioneer, Quill. Only Starter's repo is public, so the picker's pictures ship with the package: `resources/thumbnails/<slug>.jpg`, one per catalog entry, written by `bin/thumbnails.sh` from each template's `thumbnail.png` (run it when a thumbnail or the catalog changes) and served first by `TemplateCatalog::thumbnailPath()` / `StudioController::templateThumbnail`. A template an app adds to the catalog has no bundled picture and falls back to the old path — clone on the first request, then GitHub's raw URL; on the development machine a fresh install anywhere clones the private ones because the global `~/.gitconfig` rewrites `https://github.com/designer-templates/` to `https://designerdv@github.com/designer-templates/` (`url.….insteadOf` — an `includeIf gitdir:` cannot do it, a clone into `storage/studio/templates` has no git dir to match yet); without that the pick fails with GitHub's "Repository not found". A candidate joins only after the round-trip invariant, an HTTP render sweep, an edit-and-publish check, and a look at 1024–1280px (the width the canvas has on a laptop). There are no built-in templates or packaged sections any more. See `docs/site-templates.md`

### Backend (PHP)

**Services** (`src/Services/`):
- `Storage/StudioStorage` — JSON file I/O under `storage/studio/`. Draft mode (`studio.draft_mode`, default on) adds workspaces: pages/layouts/blocks/collections/site are read/written under `draft/` when `useDraft()` is active (set by StudioController's constructor + EditorPanel::boot). The **live** tree is a mirror of the installed site's files (see `Site/SiteMirror`); a write to it sets a flag (`consumeLiveChanges()`) the provider flushes to files at request end. The component library is NOT workspaced
- `PublishService` — draft mode engine on raw paths (workspace-immune): `status()` diffs draft vs live (ignores timestamps), `publishAll()` = mirror refresh (pull outside edits) → draft→live → `SiteMirror::flush()` (files; `notes` for anything it refused, e.g. a hand-written page at the same URL), `discardAll()` = refresh → live→draft, `ensureDraftSeeded()` seeds `draft/` from live on first boot. Publishing is always whole-site (shared layouts/blocks make partial publishes unsafe). Draft site is browsable at `/studio/preview[/{slug}]` — preview pages rewrite internal links to stay under the preview prefix and show a floating "Draft preview / Edit page" badge (`page.blade.php`, gated on `$preview`); a path with no page document behind it — a `[collection.field]` page such as `/blog/{slug}`, a nested or hand-written page — is rendered from its file by `Services/Site/CodePagePreview` (the runtime's resolution and static `@vite` projection, with the draft's `$site` and collections) and given the same link rewriting and badge (`partials/draft-preview.blade.php`)
- `Storage/PageRepository` — page CRUD + section ops (add/remove/reorder/duplicate/hide), slug management
- `Storage/BlockRepository` — global blocks (`storage/studio/blocks/`): a synced section instance (component_ref + variables) that pages/layouts reference via lightweight placements (`{id, block_ref, order, hidden}`); `hydrate()` expands placements in all render paths, `usage()`/`deleteEverywhere()` manage cross-page placements. Editing any placement writes to the block → updates everywhere. Placements keep position/hidden local; on disk a block is `views/components/blocks/<slug>.blade.php` and a placement is `<x-blocks.<slug> />`. Teal chrome in the canvas, "Global blocks" category in the Add-Section modal, Make global / Detach / Delete everywhere in the panel
- `Storage/LayoutRepository` — reusable layouts (`storage/studio/layouts/`): page-like docs whose `components` array contains one `@content` slot entry (id `__content__`); sections before it are the shared header, after it the shared footer. Pages opt in via `layout_ref`. The slot can't be removed/hidden/duplicated; Studio's render paths (iframe, draft preview) merge `regions()` around the page's own sections, and each layout doc is the file `views/components/layouts/<slug>.blade.php`. Every page file needs a layout (it supplies the `<head>`): new pages default to `primary()` (`main`), "None" is only offered on a site without layouts, and deleting a layout moves its pages to another (the last can't be deleted)
- `Storage/ComponentRepository` — library CRUD, `grouped()` returns categories in canonical order (`CATEGORY_ORDER`)
- `DesignSyncService` — makes the library exactly the site's sections: every `resources/designer/views/components/**/X.blade.php` with a sibling `X.yml` (excluding `layouts/` and `blocks/`); name = path slug (`sections/hero` → `sections-hero`), `tag` = dotted path (`sections.hero`), `path` kept for the source files; translates field types (`number`→text, `richtext`→textarea, `color`→colorpicker, `boolean`→toggle); removes entries whose files are gone
- `Storage/CollectionRepository` — collections (`storage/studio/collections/<name>.json`, workspaced + published like pages): `{name, title, fields: {key: {type,label,options?}}, rows: [{id,…}]}`; field types text/textarea/richtext/url/image/select/toggle/number; keys keep their case (`dateFormatted`) because sections read them
- `CollectionBinder` — resolves an instance's `bindings`: `collections.<name>` (the collection's rows), `site.<path>` (site data — **two-way** in the inspector: `EditorPanel::saveSiteValues` writes edits into the site doc, so nav + footer stay in step), `php:<expr>` / `blade:<text>` (code from the page file — evaluated for the canvas, shown as "set in code", never edited). `RenderController` passes the posted keys as `$given` so a site-bound field shows what was just typed. `PageRepository::defaultBindings()` applies a field's yml `source: collections.<name>|site.<key>` when a section is added (`CollectionRepository::resolveName` accepts doc or file names). `EditorPanel::unbindField` replaces any binding with its current value
- `Assistant/Engines` (finds `claude` / `codex` binaries, builds the non-interactive argv: `claude -p … --output-format stream-json --include-partial-messages --dangerously-skip-permissions --append-system-prompt … [--resume]`, `codex exec --json --full-auto …` / `codex exec resume`), `Assistant/Threads` (`storage/studio/assistant/threads/*.json`, not workspaced), `Assistant/SystemPrompt` (storage layout + the open page's instances + the selection), `Assistant/TurnRunner` (Symfony Process in `base_path()`, translates each CLI's JSON lines into the SSE events, appends the assistant message, keeps the session id for `--resume`)
- **Section variations** (`Assistant/SectionSnapshot` + the `section` kind of `Assistant/ImageVariations`, `partials/section-variations-modal.blade.php`): the Ask AI menu's Variations takes a picture of the section alone at 1440px with its draft values (`POST api/assistant/variations/snapshot` — the section is rendered to a string with the `preview` view and drawn by `bin/section-snapshot.mjs`, Playwright from the **app's** `node_modules`, which answers the document request itself so the browser needs no session; the feature is off without Node + Playwright), Codex draws redesign concepts from it through the image variations' job and SSE stream (`snapshot` in place of `image` on start), and the chosen one goes to the Assistant: `$store.studio.redesignSection()` → `tellAssistant()` → the `studio:chat-send {sectionId, prompt, attachments, mode}` window event, which the composer's `deliver()` sends as a Build turn once the section's chip has arrived (while a turn is running it waits in the composer). Improve is the same event with a fixed prompt and no images. - `Site/SiteReader` — files → docs. A page is Studio's only if it is a **composition** (`pageStructure()`: one `<x-layouts.*>` wrapping only section/block tags, whitespace, comments; or no wrapper); 404, `[x.y]` dynamic, nested, invalid-slug, and mixed-markup pages are **code pages** (served, editable in Code mode, never touched). Page wrapper title/description come from `meta.seo_*` ?: title/description; home page ↔ `index.blade.php`; renames delete the old file; never overwrites a file it doesn't own (note instead); new layouts start from `main` minus its sections; JSON via `JsonDocument` (formatting-preserving); also writes designer.json
- `Site/BladeTags` (lossless tag scanner: offsets, raw attribute items + whitespace, hidden-comment detection, skips comments/`@verbatim`/`<script>`), `Site/AttributeCodec` (attribute ⇄ value/binding; toggles as "1"/"0"; quote choice because Blade can't escape the delimiter), `Site/PhpLiteral` (tokenizer-based literal parser/printer — never evaluates; assoc arrays print as `(object) […]` to match JSON-decoded data), `Site/JsonDocument` (patches JSON text in place; re-encodes only the node whose structure changed, in its siblings' inline style)

### Sections (`resources/designer/views/components/`)

Sections are the installed site's own components: `resources/designer/views/components/sections/<name>.blade.php` + `<name>.yml` (any component with a `.yml` counts; `nav`/`footer` usually do too and live in layouts). Their fields are the template's contract; repeaters may declare `source: collections.<name>` or `source: site.<key>`. Use HTML comments in sections, not `{{-- --}}`, when the comment should survive into the rendered page.

**The authoring contract lives in `docs/authoring-sections.md` — read it before creating or editing any section.** How your Blade decides what becomes editable on the canvas is covered there too, and in full in `docs/inline-editing.md`. Every render path compiles with real Blade, so `@props`, `$loop`, comparisons, nested conditionals, `@php`, and nested `<x-…>` components all work.

`text`, `textarea`, `url`, `select`, `toggle`, `colorpicker`, `image`, `repeater` (sub-field types: text, textarea, url, image, select; `nestable: true` enables one child level).

### Artisan Commands

```bash
php artisan studio:sync             # Re-read the installed site (sections + pages/data) into the editor
php artisan studio:inline:verify    # THE test suite for inline editing: coverage + the byte-identical sentinel invariant + a leak check (dev only)
php artisan studio:publish          # Publish compiled assets to public/vendor/studio (--remove reverts; also: vendor:publish --tag=studio-assets)
php artisan studio:templates:sync   # Clone/pull the template repos (--list, --template=, --force)
php artisan studio:templates:import # Install a template into resources/designer + public/designer (--force replaces the installed site)
php artisan studio:templates:link   # Local only: link the installed site to a template folder (path or slug; --install/--export settle a mismatch; --unlink) — every site write is exported back into its files/ at request end
php artisan studio:templates:export # Push the installed site into the linked template folder by hand (--force overwrites hand edits made in the folder)
php artisan studio:dev-reset        # Fresh-install state: deletes the site, its runtime provider, and editor data (--template= to reinstall)
php artisan studio:uninstall        # Remove Studio's editor data (--keep-data); the site keeps working
```

## Gotchas

- **The files are the live site.** Editing `resources/designer` (Code mode, the Assistant, your own editor) is live at once; Studio pulls it in on the next `SiteMirror::sync()`. Never hand-edit `storage/studio/{pages,layouts,…}` (the live mirror) — it is rebuilt from the files. `storage/studio` holds nothing the site needs: a fresh deploy rebuilds it on the first `/studio` visit
- **SiteReader and SiteWriter must stay exact inverses.** Re-check after touching either, from a script that bootstraps a **throwaway** Laravel app with this package path-symlinked — never the host, whose `resources/designer` is a real site that `replace: true` deletes (`require vendor/autoload.php; $app = require bootstrap/app.php; $app->make(Kernel::class)->bootstrap();`): `SiteInstaller::install($slug, replace: true)`, hash every file in `resources/designer`, `SiteMirror::flush()` → nothing may change; then `refresh(true)` + `flush()` → still nothing. Verified on all 40 public templates in the site-templates org (2026-09-11, Laravel 13). Two writer rules that came out of it: a page's layout tag that has no `title` only gains one when an SEO title is set (the layout's own default — often just the site name — is the page's `<title>` otherwise), and a hand-written home page keeps its designer.json entry (its file is `index.blade.php`, not `{home_slug}.blade.php`). A form difference between what Studio stores and what the reader produces (e.g. `hidden: false`, resolved default variables) is fine — the writer compares values, not forms — but anything that makes an unchanged doc re-write a file is a bug
- To simulate removing Studio in the host: add `"dont-discover": ["designer/studio"]` under `extra.laravel` in the host's composer.json, `php artisan package:discover`, request the site (all pages must still serve; `/studio` 404s), then revert and re-discover
- The runtime provider is the app's file once written: to ship a runtime change, update the stub AND consider existing installs (they keep their copy; `@version` in its docblock)
- `Livewire.dispatch()` names and the postMessage protocol (`studio:*`) are shared contracts between `EditorPanel`, `home.blade.php`, `iframe.blade.php`, and `studio.js` — change them everywhere or nowhere. `studio:open-inspector {sectionId}` (iframe → editor) is the one that opens the panel; `studio:section-selected` deliberately does not. `studio:selection-released` (iframe → editor) drops the editor's `selectedId` without telling Livewire; `studio:deselected` tells Livewire too. `studio:canvas-down` (iframe → editor, on every pointerdown in the canvas) is how a flyout over the canvas knows to close — a click in the iframe never reaches the editor's document. `studio:corners {tl, tr, br, bl}` (editor → iframe, on every frame load and resize — `StudioEditor.syncCorners()`) tells the canvas how much of each of its corners the stage's rounded window cuts away; `StudioPreview.roundCorners()` then gives any section whose corner sits inside a cut corner the radius that keeps its outline whole (`--studio-corners` on the wrapper, read by `.studio-section::after`; measured once a frame on scroll and layout change), so the outline follows the stage's curve instead of being cut off by it — and stays square everywhere else (a tablet width, the far side of the Code view's split). `studio:context {sectionId, locator, reveal}` (editor → iframe) is what the Assistant's composer is holding — the picked element (`locator`: child indexes from `[data-section-content]`, which `describeElement()` now reports beside the readable `path`) or just the section; the canvas marks it in the pick tool's dashed violet (`[data-studio-context]`, or `.studio-section.is-context::after`), puts the mark back after a re-render, and scrolls to it on `reveal`. `studio:focus-field {sectionId, key, on}` (editor → iframe) is the inspector's caret: the canvas haloes what that field renders, under its label, through the same `queuePaint` the code-to-canvas highlight uses, repainting on scroll and re-render. `studio:canvas-loaded` (a window event in the editor, on every frame load) is the cue to say such things again.
- **Files changed outside the editor → dispatch `studio:code-saved` and nothing else.** `EditorPanel::refreshAfterCodeSave` runs `SiteMirror::sync()` and then dispatches `studio:refresh-preview` itself. The canvas renders sections from the synced library (`$component->html`), so a `studio:refresh-preview` sent beside `studio:code-saved` races the sync and reloads the old section (the Assistant did this; you had to refresh by hand). Refresh directly only when nothing was synced.
- After editing `resources/css|js`, run `npm run build` (or keep `npm run dev` watching). Asset URLs come from `Support\StudioAssets::url()`: a published copy in `public/vendor/studio` wins (static file, filemtime cache buster); otherwise `AssetController` serves the package `dist/` with a per-file mtime buster. If the editor looks stale, check for a forgotten published copy (`php artisan studio:publish --remove`).
- **Render nested Blade through `Support\NestedBlade::render()`, never `Blade::render()`,** whenever the caller catches the failure (sections, lifted layout chrome, `php:`/`blade:` bindings). Laravel's `View::render()` answers any exception with `flushState()`, which wipes the component/section stacks of the view still rendering around it — the canvas iframe then 500s with "Undefined array key 0" instead of showing one broken section in place. `NestedBlade` snapshots the factory's render state and restores it before rethrowing
- **Templates must hold together at 1024–1280px.** That is the canvas width on a laptop (the screen minus the rail and an open right column — ~44px and ~366px), so a two-column hero that only works from 1280 looks broken in the editor even when the live site is fine on a wide monitor
- **`studio:inline:verify` is the only test inline editing has** — run it from the host after any change to `Services/Inline/`, `SectionRenderer`, or the canvas render path. Baseline: `Coverage: 365/369 fields mapped across 62 sections`, `Inertness: 57 identical, 0 diverged, 5 unrenderable, 577 sentinels`. The inertness line is the load-bearing one: stripping the sentinels must reproduce the plain render byte for byte, because a sentinel must describe the page and never change it.
- **Route every new canvas affordance through `editabilityOf`, with the section id the HIT resolved to** — not the one from the DOM ancestor. Five separate bugs during development were a gate consulted with the wrong or missing input; the gate itself was right every time.
- **Never `display: none` a section's `.studio-rail`.** It is an in-flow 50px box whose height `[data-section-content]`'s negative margin takes back; removing it from the layout shifts that section 50px up over its neighbour (the focus scrim did exactly this on 2026-09-26). Hide it with `visibility: hidden`. Likewise, never cover sections with one fixed layer that has to out-stack the site's CSS — a dim scrim lost that fight in Chrome and, once a tall section filled the viewport, showed nothing anyway; the edited section is isolated as a card instead
- **The canvas iframe loads `studio.js` only, never `studio.css`.** Anything rendering inside the frame needs its styles in `iframe.blade.php`'s pushed `<style>` block.
- **`DataBag::wrap([])` is an object, and objects are always truthy** — so `@if ($link->children ?? false)` is true on the canvas but false on the live site (where rows arrive as `stdClass` with a plain `[]`). A nestable repeater row with no children renders differently in the editor than on the published page. Pre-existing, visible in Pilot's `nav`/`footer`, not yet fixed.
- **A document handed to headless Chromium cannot load from a local site by default.** `bin/section-snapshot.mjs` fulfils the page request itself, so Chromium gives the document no address space and blocks its requests to `designer.test` (every image `net::ERR_FAILED`, broken-image icons in the picture). The `--disable-features=LocalNetworkAccessChecks,…` launch argument is what lets the section's images and fonts in — keep it.
- **A turn belongs to no connection.** The CLI says nothing while a model composes a long edit, and nginx closes a FastCGI stream that sends nothing for 60s (`upstream timed out … while reading upstream` in its error log). Two things keep that from costing a turn: `TurnRunner::run()` reads the process non-blocking and emits a `ping` (an SSE comment) every 5s of silence, so the stream never goes quiet; and a connection that drops anyway no longer stops the turn — every event is appended to `turns/<id>.events` with a number that travels as the SSE `id`, the browser's `EventSource` reconnects by itself with `Last-Event-ID`, and `AssistantController::stream()` hands a turn that is not `pending` to `TurnRunner::follow()`, which replays what was missed and tails the log to the end (a log untouched for 90s while `running` means the process is gone). Only Stop (the `.stop` flag) ends a turn early; a failed reply keeps its reason in the message's `error`, shown under the cut-off text.
- **An Assistant turn outlives PHP's execution limit.** `TurnRunner::run()` calls `set_time_limit(0)` and `ignore_user_abort(true)`: the reply is appended to the thread only when the turn ends (`finish()`), so a request killed at 30s left the CLI running as an orphan — the files changed, and the transcript showed no reply. Keep both calls ahead of anything long.
- **Never take file contents from `$request->input()`/`validate()`.** Laravel's `TrimStrings` middleware strips leading and trailing whitespace from request input, which silently eats a saved file's trailing newline. `CodeController::rawContents()` reads `contents` off the raw JSON body instead; validation still guards the shape.
- **Never put a Monaco editor or model inside an Alpine store or `x-data`.** Alpine deep-proxies what it holds, and Monaco's object graphs are large and getter-heavy — doing so hangs `openFile()` silently. Code mode keeps them in the plain `studioCodeBuffers` object beside the store (`home.blade.php`); only serialisable state (tabs, active path, dirty flags) is reactive.
- The compiled asset list lives in several places that must stay in sync when files are added: `StudioAssets::FILES` (drives `studio:publish` + the provider's `studio-assets` publish tag), `AssetController::$allowedFiles` (adds MIME types), Vite's `ASSET_FILES` (`vite.config.js`), and `MONACO_FILES` in `esbuild.monaco.mjs`.
