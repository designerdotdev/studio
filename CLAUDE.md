# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Designer Studio is a Laravel package (not a standalone app) that provides a visual page builder for Laravel applications. **The site it edits is a set of ordinary files in the host app** — a DevDojo site-template installed into `resources/designer` + `public/designer` and served by `app/Providers/DesignerServiceProvider.php`, a runtime Studio writes into the app that has no dependency on the package (remove Studio and the site keeps working). Studio itself keeps JSON documents (no database) as its working model — a mirror of those files plus a draft — and uses Livewire 3 for the editor panel and an iframe canvas rendered server-side. The host app for local development is the repo two levels up (`/Users/tonylea/Sites/designer`), which path-symlinks this package via composer.

## Build Commands

```bash
npm run build          # Build frontend assets (Vite → dist/)
npm run dev            # Watch mode: builds Monaco once, then rebuilds dist/ on every change (re-publishing to the host's public/vendor/studio if published assets exist)
```

There are no tests or linting configured in this package. Verify changes against the host app (`php artisan serve` from the repo root, then hit `/studio`).

## Architecture

### Package Structure

- **Namespace**: `Designer\Studio` (PSR-4 from `src/`)
- **Service Provider**: `StudioServiceProvider` — singletons, editor routes, views, Livewire components, `@studioStyles`/`@studioScripts` directives, the site's components path for canvas renders, and a `terminating` flush of live documents to files (draft mode off). It registers **no public routes** — the installed runtime serves the site
- **Config**: `config/studio.php` — route prefix, middleware, optional `gate`, `draft_mode`, `dev_mode`, storage path, iframe CDN options, and `templates` (clone cache path + the catalog: 11 templates, each with a `category` — landing or business — that the onboarding picker filters on)
- **Hardening**: every route has parameter constraints (`[a-z0-9-]+` slugs/names); upload (30/min), publish/discard (12/min) are throttled; `StudioController::editorNotices()` surfaces floating canvas banners for unprotected-in-production and unwritable-storage states; the editor shows a small-screen overlay below `lg`
- **Concurrent edits**: `EditorPanel::$docVersions` tracks page/layout `updated_at` at load; `guardConflict()` blocks every mutation with a Reload toast if the doc changed elsewhere (block-content edits skip the guard — blocks are shared by design)
- **The installed site** (`Support/SitePaths` is the single source for its locations): `resources/designer/{designer.json, css, data/site.json, data/collections/*.json(+yml), views/pages, views/components/{sections,layouts,blocks,…}}` and `public/designer/{images,js,…,uploads}`. `designer.json` (`Services/Site/SiteManifest`) holds what a page file can't: page titles/description/order/meta (SEO)/previous_slugs, home slug, layout and block names — the runtime reads it for SEO tags and renamed-page 301s
- **The runtime** (`stubs/DesignerServiceProvider.php.stub` → `app/Providers/DesignerServiceProvider.php`, written + registered by `Services/Site/RuntimeInstaller` via `ServiceProvider::addProviderToBootstrapFile`, self-healed on editor load, never overwritten once it exists): registers the components path, serves from `Route::fallback` (app routes always win, `route:cache`-safe): pages (`/` → `index`, flat file beats `dir/index`), `[collection.field]` dynamic pages (row shadows the collection, `$entries` = all rows), `/sitemap.xml`, home-slug and `previous_slugs` 301s, the site's `404.blade.php`; shares `$site`/collections/markdown content as objects; swaps Vite for a static projection of `resources/designer/*` entries (Tailwind browser CDN + inlined `<style type="text/tailwindcss">`, other entries go to the app's Vite); injects per-page SEO tags the layout doesn't write. Mirrors Pocketknife's Laravel runtime (`~/devdojo/pocketknife/laravel`) + DevDojo's DynamicPages
- **Claiming `/`**: `Support/WelcomeRoutePruner` auto-removes the stock Laravel welcome route from the host's `routes/web.php` (strict regex — customized routes are never touched) so the home page serves at `/`. Runs on install, on publish (`home_claimed` → toast), and on editor load; requires `views/pages/index.blade.php`; clears the route cache when needed. `Support/SiteUrls::pageUrl()` is the single source for public page URLs; `ownsRoot()` = the app has no GET `/` of its own (then the home page is served at `/{home_slug}` and the editor shows an `app-owns-root` notice)
- **Dev mode**: `Support/DevMode::enabled()` — `config('studio.dev_mode')` (env `STUDIO_DEV_MODE`), default null = local environment only. When on (server gate + `$store.studio.devMode` toggle in the hamburger menu), the inspector header shows an Edit-code button that opens a Monaco modal (Blade/YAML tabs; the JSON keys stay `html`/`yaml`) for the selected section's `.blade.php` + `.yml` (`DesignSyncService::sourceFiles`). `DevModeController` (`GET|PUT /studio/api/dev/components/{name}`) validates the YAML, writes both files in place (contents from the raw body — TrimStrings), runs `SiteMirror::sync()`; the frontend then refreshes the preview and dispatches `studio:code-saved` (EditorPanel re-syncs and reloads fields)
- **Editor modes**: `$store.studio.mode` is `preview | edit | code`, persisted in `localStorage['studio.mode']`, **first-run default `preview`**. A segmented control in the topbar switches them; the Code segment needs BOTH the server gate (`DevMode::enabled()`) and the user's dev-mode toggle (`$store.studio.codeAvailable`), and turning dev mode off while in Code mode falls back to Edit. The editor sends `studio:mode` to the iframe, which also reads the mode from localStorage at boot (the canvas document is rebuilt on every refresh). In **Preview** the iframe adds `html.studio-preview` — chips, toolbars, insert zones and section outlines are hidden in CSS, `Studio.preview.select/addAt` refuse to run, the context menu stands down, and links navigate: same-origin single-segment hrefs post `studio:navigate` and `StudioEditor.navigate()` moves the whole editor window to that page's editor URL (resolved against `window.__studioPages`), everything else opens in a new tab
- **Code mode**: `Services/CodeWorkspace` is the single authority for which files exist and how a browser path becomes a real one. Paths are real paths relative to the app root, in **two views** toggled in the Files panel (localStorage `studio.code-view`): *Designer* lists only the site — `resources/` → `designer/` and `public/` → `designer/`; *Laravel* lists the host app's own `LARAVEL_DIRS` (`app bootstrap config database lang public resources routes tests`) with the site's folders tinted via each node's `design` flag. A file has one path in both views (no aliasing). `storage/` is deliberately absent (it holds Studio's JSON docs) and hidden files are never walked or resolved, so `.env` is unreachable. Every path is realpath-checked against its root, `..`, hidden files and non-allowlisted extensions rejected, 512 KB cap, 4000-node walk cap. Saves under the site validate YAML/JSON first. `CodeController` (`/studio/api/code/{tree,file,section}`, 404 unless dev mode) reads/writes/creates/deletes; any write under the site runs `SiteMirror::sync()` and returns `synced: true`, and the frontend then refreshes the preview + dispatches `studio:code-saved`. "New section" scaffolds `views/components/sections/<name>.blade.php` + `.yml`; deleting either half of a section removes the pair. The UI: `$store.code` holds the flat tree (`partials/file-tree.blade.php`, rendered from `CodeWorkspace::tree()`'s depth/parent list — no recursion) in the sidebar's `files` panel, and `partials/code-pane.blade.php` holds tabs over one Monaco instance with a model per file (undo history survives tab switches). Monaco loads on the first file open, not on entering Code mode. `codeSplit`/`codeSize` (localStorage `studio.code-split`/`studio.code-size`) put the live preview beside the editor behind a drag seam
- **Command palette**: ⌘K opens it (it used to open the section library directly — "Add section…" is now its first entry). Alpine-only, defined in `home.blade.php`; commands are filtered by a `when` flag so mode/panel entries only appear where they apply, and in Code mode the workspace's files join the list as quick-open
- **Dependencies**: livewire/livewire, symfony/yaml, symfony/process (git, for template sync) — no Filament, no Katana
- **Site templates**: whole starter sites in their own git repos (DevDojo `site-templates` format); the catalog offers the org's public landing and business templates — Pilot, Amber, Draft, Signal, Reply, Lumen (landing) and Monarch, Stone, Strata, Crema, Norden (business); the org's portfolio/blog/personal templates and its private repos are deliberately left out. A candidate joins only after the round-trip invariant, an HTTP render sweep, an edit-and-publish check, and a look at 1024–1280px (the width the canvas has on a laptop). There are no built-in templates or packaged sections any more. See `docs/site-templates.md`

### Backend (PHP)

**Services** (`src/Services/`):
- `Storage/StudioStorage` — JSON file I/O under `storage/studio/`. Draft mode (`studio.draft_mode`, default on) adds workspaces: pages/layouts/blocks/collections/site are read/written under `draft/` when `useDraft()` is active (set by StudioController's constructor + EditorPanel::boot). The **live** tree is a mirror of the installed site's files (see `Site/SiteMirror`); a write to it sets a flag (`consumeLiveChanges()`) the provider flushes to files at request end. The component library is NOT workspaced
- `PublishService` — draft mode engine on raw paths (workspace-immune): `status()` diffs draft vs live (ignores timestamps), `publishAll()` = mirror refresh (pull outside edits) → draft→live → `SiteMirror::flush()` (files; `notes` for anything it refused, e.g. a hand-written page at the same URL), `discardAll()` = refresh → live→draft, `ensureDraftSeeded()` seeds `draft/` from live on first boot. Publishing is always whole-site (shared layouts/blocks make partial publishes unsafe). Draft site is browsable at `/studio/preview[/{slug}]` — preview pages rewrite internal links to stay under the preview prefix and show a floating "Draft preview / Edit page" badge (`page.blade.php`, gated on `$preview`)
- `Storage/PageRepository` — page CRUD + section ops (add/remove/reorder/duplicate/hide), slug management
- `Storage/BlockRepository` — global blocks (`storage/studio/blocks/`): a synced section instance (component_ref + variables) that pages/layouts reference via lightweight placements (`{id, block_ref, order, hidden}`); `hydrate()` expands placements in all render paths, `usage()`/`deleteEverywhere()` manage cross-page placements. Editing any placement writes to the block → updates everywhere. Placements keep position/hidden local; on disk a block is `views/components/blocks/<slug>.blade.php` and a placement is `<x-blocks.<slug> />`. Teal chrome in the canvas, "Global blocks" category in the Add-Section modal, Make global / Detach / Delete everywhere in the panel
- `Storage/LayoutRepository` — reusable layouts (`storage/studio/layouts/`): page-like docs whose `components` array contains one `@content` slot entry (id `__content__`); sections before it are the shared header, after it the shared footer. Pages opt in via `layout_ref`. The slot can't be removed/hidden/duplicated; Studio's render paths (iframe, draft preview) merge `regions()` around the page's own sections, and each layout doc is the file `views/components/layouts/<slug>.blade.php`. Every page file needs a layout (it supplies the `<head>`): new pages default to `primary()` (`main`), "None" is only offered on a site without layouts, and deleting a layout moves its pages to another (the last can't be deleted)
- `Storage/ComponentRepository` — library CRUD, `grouped()` returns categories in canonical order (`CATEGORY_ORDER`)
- `DesignSyncService` — makes the library exactly the site's sections: every `resources/designer/views/components/**/X.blade.php` with a sibling `X.yml` (excluding `layouts/` and `blocks/`); name = path slug (`sections/hero` → `sections-hero`), `tag` = dotted path (`sections.hero`), `path` kept for the source files; translates field types (`number`→text, `richtext`→textarea, `color`→colorpicker, `boolean`→toggle); removes entries whose files are gone
- `Storage/CollectionRepository` — collections (`storage/studio/collections/<name>.json`, workspaced + published like pages): `{name, title, fields: {key: {type,label,options?}}, rows: [{id,…}]}`; field types text/textarea/richtext/url/image/select/toggle/number; keys keep their case (`dateFormatted`) because sections read them
- `CollectionBinder` — resolves an instance's `bindings`: `collections.<name>` (the collection's rows), `site.<path>` (site data — **two-way** in the inspector: `EditorPanel::saveSiteValues` writes edits into the site doc, so nav + footer stay in step), `php:<expr>` / `blade:<text>` (code from the page file — evaluated for the canvas, shown as "set in code", never edited). `RenderController` passes the posted keys as `$given` so a site-bound field shows what was just typed. `PageRepository::defaultBindings()` applies a field's yml `source: collections.<name>|site.<key>` when a section is added (`CollectionRepository::resolveName` accepts doc or file names). `EditorPanel::unbindField` replaces any binding with its current value
- `Assistant/Engines` (finds `claude` / `codex` binaries, builds the non-interactive argv: `claude -p … --output-format stream-json --include-partial-messages --dangerously-skip-permissions --append-system-prompt … [--resume]`, `codex exec --json --full-auto …` / `codex exec resume`), `Assistant/Threads` (`storage/studio/assistant/threads/*.json`, not workspaced), `Assistant/SystemPrompt` (storage layout + the open page's instances + the selection), `Assistant/TurnRunner` (Symfony Process in `base_path()`, translates each CLI's JSON lines into the SSE events, appends the assistant message, keeps the session id for `--resume`)
- `SectionRenderer` — **the one place a section becomes HTML** in Studio (canvas, live edits, draft preview, thumbnails): Blade-compiles the section's own source with `RenderContext::globals()` (`$site` + every collection by file name, DataBag-wrapped so `$item['x']` and `$item->x` both resolve) under its values — the same data the runtime shares. A render failure is reported and shown in place rather than blanking the page
- `Templates/TemplateSync` — clones/fast-forwards/prunes the git repos in `studio.templates.catalog` into `storage/studio/templates` (self-ignoring cache; `ensure($slug)` clones on demand). A clone with uncommitted or unpushed work is reported and skipped, never reset (`--force` discards)
- `Templates/TemplateChrome` lifts fonts, theme CSS (the `@vite` stylesheets), scripts (head, then the ones a layout loads at the end of `<body>`) and body/html classes out of a layout file (used by `SiteChrome`); head fragments compile one element at a time against the site data plus the layout's literal `@props` defaults (`{{ $favicon }}`), so one it can't resolve costs only itself; `Templates/TemplateAssets` moves a template's public URLs under `/designer`; `Templates/TemplateCatalog` = the config catalog for the picker (`all()` + `categories()` for its filters)
- `Storage/SiteRepository` — the site document (`site/data.json`, workspaced): `data` (the `$site` bag = `data/site.json`), `home_slug` (= designer.json `home`), `template`; `setData($path, $value)`. Fonts/CSS/scripts are NOT stored: `Support\SiteChrome` reads them from the site's main layout file (via `Templates/TemplateChrome`) and stamps them onto the canvas, previews, and draft preview, handing the CSS to Tailwind's browser build as `<style type="text/tailwindcss">`

- `Site/SiteInstaller` — installs a catalogued template: `TemplateSync::ensure()` (clone on demand), copies `files/resources` → `resources/designer` and `files/public` → `public/designer` (dotfiles skipped; text files get public URLs moved via `Templates/TemplateAssets` and `@vite('resources/…')` → `resources/designer/…`), drops the compiled views (and OPcache entries) of the site's Blade files — a replacing site reuses the old one's paths, and compiled views are named by path — writes `designer.json` (titles/order from `template.json`), `RuntimeInstaller::install()`, `SiteMirror::rebuild()`, claims `/`. Refuses to overwrite an installed site unless `$replace`
- `Site/SiteMirror` — keeps live JSON == files. `fingerprint()` hashes every mirrored file (+ section ymls); `refresh()` re-reads only docs whose own files changed (all of them when designer.json or the section set changed), writes the live tree, and propagates each change into the draft **only where the draft still matched the old live doc**; `flush()` = `SiteWriter` over the live docs; `rebuild()` forgets every doc and reads afresh; `reservedSlugs()` = hand-written page names. State (hashes + per-doc file path and instance ids in file order) in `storage/studio/mirror.json`. Callers: editor load, publish/discard, Code mode saves, dev-mode modal saves, `studio:code-saved` (Assistant), `studio:sync`
- `Site/SiteReader` — files → docs. A page is Studio's only if it is a **composition** (`pageStructure()`: one `<x-layouts.*>` wrapping only section/block tags, whitespace, comments; or no wrapper); 404, `[x.y]` dynamic, nested, invalid-slug, and mixed-markup pages are **code pages** (served, editable in Code mode, never touched). Layout regions = managed tags before/after `{{ $slot }}` in `<body>`; blocks = `components/blocks/*.blade.php` holding one section tag; hidden = a Blade comment holding exactly one tag; collections keep their file name as `source` (doc name kebab), `studio_ids` when rows had none. Instance ids stay stable (`withIds`: same position + same section, else same values)
- `Site/SiteWriter` — docs → files, **in place**: `rebuild()` matches the file's managed tags to instances by the recorded ids (only when the file's hash is unchanged), keeps an unchanged tag's text, edits a changed one attribute by attribute (`AttributeCodec`; a new attribute only when it differs from the field default), splits each gap into positional *anchor* markup (stays put: `</main>`, `@if`) and a *prelude* of whitespace/comments (travels with its tag). Page wrapper title/description come from `meta.seo_*` ?: title/description; home page ↔ `index.blade.php`; renames delete the old file; never overwrites a file it doesn't own (note instead); new layouts start from `main` minus its sections; JSON via `JsonDocument` (formatting-preserving); also writes designer.json
- `Site/BladeTags` (lossless tag scanner: offsets, raw attribute items + whitespace, hidden-comment detection, skips comments/`@verbatim`/`<script>`), `Site/AttributeCodec` (attribute ⇄ value/binding; toggles as "1"/"0"; quote choice because Blade can't escape the delimiter), `Site/PhpLiteral` (tokenizer-based literal parser/printer — never evaluates; assoc arrays print as `(object) […]` to match JSON-decoded data), `Site/JsonDocument` (patches JSON text in place; re-encodes only the node whose structure changed, in its siblings' inline style)

**Livewire** (`src/Livewire/`):
- `EditorPanel` (`studio::editor-panel`) — the entire side panel: sections list, inspector (field editing), Layout tab (assign/create/rename/delete layouts), page settings. Saved variables never include bound keys; site-bound ones are written to the site doc instead (`saveSiteValues`), and the inspector shows code bindings as a locked "Set in code" panel and site bindings with a "Site-wide" note + Unlink (`unbindField`). Holds both the page's sections and its layout's sections; every section op routes to PageRepository or LayoutRepository by instance-id membership (`isLayoutSection`), so editing a layout section from any page updates all pages using it. Listens for `studio:select-section`, `studio:add-section` (accepts `scope: page|layout`), `studio:section-action`, `studio:undo-delete`; emits `studio:refresh-preview`, `studio:to-iframe`, `studio:toast` (supports `action: {label, dispatch}` for toast buttons like Undo), `studio:page-meta-updated` browser events. Section deletion is confirm-free and undoable: the raw instance + position is captured in `$lastDeleted` and restored by the toast's Undo (single-level; page/layout/block-everywhere deletions keep their confirms)

- `PagesPanel` (`studio::pages-panel`) — list/rename/duplicate/delete/reorder pages (`order` on the page doc, `PageRepository::reorder`), "Set as home" writes `home_slug` into the site doc (`SiteUrls::homeSlug()` is the single reader — site doc first, config fallback)
- `MediaPanel` (`studio::media-panel`) — a thin frame; the browser is Alpine over `MediaController`'s JSON endpoints (`GET/POST/PATCH/DELETE /studio/api/media…`) backed by `Services/MediaLibrary` (images only, paths relative to `public/designer`, `..` rejected, URLs root-relative `/designer/…` so page files work on any host). Picker mode: `window.Studio.mediaPick()` resolves with a URL; image fields and repeater sub-images have a Library button
- `ContentPanel` (`studio::content-panel`) — collections → rows → entry form (`livewire/content/field.blade.php` incl. a contenteditable richtext editor), schema editor, create/delete. Row saves dispatch `studio:refresh-preview`; "Edit in Content" from the inspector fires the `studio:open-collection` window event
- `AssistantPanel` (`studio::assistant-panel`, dev mode only) — threads + composer; streaming runs in Alpine against `AssistantController` (SSE). Listens to `studio:select-section` for the context chip; the crosshair sends `studio:element-select` to the iframe, which answers `studio:element-selected {sectionId, ref, path, tag, text}` (relayed as a window event). After a turn: `studio:refresh-preview` + `studio:code-saved`

**Controllers** (`src/Http/Controllers/`):
- `StudioController` — editor page (onboarding until `SitePaths::installed()`; then runtime self-heal + `SiteMirror::sync()` on every load), iframe doc, component/block previews, template install (`applyTemplate` → `SiteInstaller`) + thumbnails (local clone or GitHub raw), page CRUD API, image upload (`public/designer/uploads/`)
- `AssetController` — serves the compiled `dist/` assets (allowlist mirrors `StudioAssets::FILES`)
- `MediaController` — JSON for the Media panel (see `MediaLibrary`)
- `AssistantController` — `GET api/assistant/engines`, `POST api/assistant/turn` (records the user message, returns a turn id), `GET api/assistant/stream/{turn}` (SSE: `text`, `activity`, `files`, `done`, `error`), `DELETE api/assistant/stream/{turn}` (stop flag). 404 unless `DevMode::enabled()`

**DTOs**: `PageData`, `ComponentData` — `ComponentData::resolveVariables($overrides, usePreviewDefaults:)` is the single source of truth for merging stored values over field defaults (repeaters always resolve to arrays).

### Frontend

- `resources/js/studio.js` — single bundle for BOTH the editor window and the preview iframe. Contains: toasts (`Studio.toast`), the editor↔iframe postMessage bridge, keyboard shortcuts, save-status tracking (Livewire commit hooks), SortableJS drag-reorder helper, upload helper, `Studio.codeEditor` (lazy-loads the slim Monaco bundle on first modal/file open — `dist/studio-monaco.js` + worker files built by `esbuild.monaco.mjs`, HTML/YAML/CSS/JS languages, with `studio-dark` and `studio-light` themes kept in step by `StudioMonaco.syncTheme()`; studio.js carries no editor code) + `Studio.codeModalOpen` (global shortcuts stand down while the dev-mode code modal is open), and the iframe-side `StudioPreview` runtime (selection overlay, live re-render). Boots per-document based on `window.__studioPreview` or `#studio-canvas-frame`.
- **Live re-rendering is server-side.** `StudioPreview.render()` queues a section, coalesces ~90ms of edits, and POSTs `{sections:[{id, ref, variables}]}` to `studio.api.render`; the response markup is swapped into `[data-section-content]`. A section already awaiting a response is re-queued rather than double-requested. There is no client-side Blade renderer any more (`blade.js` was deleted) and no `templates` payload in the iframe — only refs and current values travel with the document.
- `resources/css/studio.css` — Tailwind 4 with the editor design tokens (`@theme`: shell/panel/raised/ink/soft/accent…) and all `s-*` component classes (buttons, inputs, popovers, modals, preview cards, toasts).
- Editor chrome typeface: Geist (Google Fonts, loaded in the app layout).

### Views

- `components/layouts/app.blade.php` — editor shell: a full-width 48px **topbar** (`s-topbar`, `bg-shell`, hairline below) that renders the `menu` slot (logo/menu `s-box-btn`, dropdown opens below) before the page's `topbar` slot; under it three columns — the 48px **rail** (`s-rail`, 32px buttons, hairline right; its left edge lines up under the menu button via the topbar's `pl-2`) with Assistant (dev mode) / Sections / Pages / Content / Media (+ Files in Code mode), the 320px `bg-panel` sidebar (hairline right; panel header rows are `h-11` with a bottom hairline), and `main`. The canvas is flush: the preview's square `s-frame` fills the dotted `s-canvas` surface edge to edge (no padding, radius or shadow), so the dots only show beside a tablet/mobile preview, which gets hairline side edges (`is-narrow`); Code mode's editor pane is an `s-frame` on the same surface, and the split's `s-code-seam` is a 1px hairline between them with an 8px grab area (accent on hover). The topbar's `s-box-btn` buttons (menu, sidebar toggle) are flat like the nav buttons: no border or fill until hovered (`bg-wash`). `$store.studio.rail` + `setRail(name, force)` (same item again collapses the panel; persisted in localStorage `studio.rail`; fires the `studio:rail` window event). `home.blade.php` mounts the five panels in the sidebar slot, one visible at a time; selecting on the canvas forces the Sections panel. The sidebar collapses via `$store.studio.sidebar` (localStorage `studio.sidebar`); the toggle sits beside the menu button. **Themes:** dark is the default; `$store.studio.toggleTheme()` (menu → Light mode) sets `html.studio-light`, persisted in localStorage `studio.theme` and applied by an inline head script before first paint. All chrome colours are `@theme` tokens overridden under `html.studio-light` in `studio.css`; hover tints use the `wash` / `wash-strong` / `wash-faint` tokens instead of `bg-white/N` so they flip with the theme
- `home.blade.php` — editor page: topbar grouped left/centre/right (menu + sidebar toggle + back/forward/reload | a bordered **URL bar** (`s-urlbar`, max-w-xl) showing `host / slug` with the save-status dot and Saving/Saved/Offline text, hover-reveal chevron + open-draft/live link on the right, click opens the pages dropdown incl. "New page" | Preview/Edit/Code `s-seg`, split toggle (Code mode), desktop/tablet/mobile `s-seg`, Publish popover), canvas iframe, Add-Section modal (live scaled preview iframes per component), create-page modal
- `livewire/editor-panel.blade.php` + `livewire/fields/*.blade.php` — panel views; field partials: text, url, textarea, select, toggle, colorpicker, image (upload + Library picker), repeater (+ `sub-input` shared partial; bound state + bind menu). `livewire/pages-panel`, `media-panel`, `content-panel` (+ `content/field`, `content/schema-editor`), `assistant-panel`
- `iframe.blade.php` — canvas preview document: section wrappers with hover/selection overlay, name chips, floating toolbar, insert-between affordances; exposes `window.__studioPreview`. Dev-mode-only chrome (`</>` toolbar button, Edit code menu item) toggles via `html.studio-devmode` (localStorage `studio.devmode` + `studio:devmode` postMessage). Shortcuts: ⌘K add-section, ⌘D duplicate, ⌘↑/⌘↓ reorder, ⌫ delete
- `preview.blade.php` — non-interactive render used by picker + onboarding thumbnails
- `onboarding.blade.php` — first-run template picker over `TemplateCatalog` (the config catalog, with each repo's `thumbnail.png`; downloaded on pick). Applying one runs `SiteInstaller`
- `page.blade.php` — the **draft preview** document (the live site is rendered by the runtime from the page files). Renders the full head from `page.meta` (see `EditorPanel::META_KEYS`): title/description/canonical/keywords, combined robots tag (draft previews force noindex), full Open Graph set, Twitter card/site/creator, per-page favicon + theme-color, validated JSON-LD, and verbatim `head_html`. The runtime's `withSeo()` mirrors the same tags on the live site — keep them in sync. Page-tab UI groups these as Search listing (with live result preview) + collapsible Social sharing + Advanced

### Sections (`resources/designer/views/components/`)

Sections are the installed site's own components: `resources/designer/views/components/sections/<name>.blade.php` + `<name>.yml` (any component with a `.yml` counts; `nav`/`footer` usually do too and live in layouts). Their fields are the template's contract; repeaters may declare `source: collections.<name>` or `source: site.<key>`. Use HTML comments in sections, not `{{-- --}}`, when the comment should survive into the rendered page.

**The authoring contract lives in `docs/authoring-sections.md` — read it before creating or editing any section.** Every render path compiles with real Blade, so `@props`, `$loop`, comparisons, nested conditionals, `@php`, and nested `<x-…>` components all work.

### Field Types

`text`, `textarea`, `url`, `select`, `toggle`, `colorpicker`, `image`, `repeater` (sub-field types: text, textarea, url, image, select; `nestable: true` enables one child level).

### Routes (prefix from `studio.path`, default `studio`)

- `GET /studio` — editor (or onboarding until a site is installed)
- `GET /studio/page/{slug}/iframe` — canvas preview document
- `GET /studio/preview/component/{name}` / `GET /studio/preview/block/{slug}` — section picker thumbnails
- `POST|PUT|DELETE /studio/api/pages…` — page + section CRUD
- `POST /studio/api/render` — live canvas re-render (batched; throttled 600/min)
- `GET /studio/preview/thumbnail/{name}` — a template's `thumbnail.png` (local clone, else a redirect to GitHub raw)
- `POST /studio/api/upload` — image uploads (`public/designer/uploads`)
- `POST /studio/api/onboarding/apply-template` — install a template
- `GET|PUT /studio/api/dev/components/{name}` — dev-mode section source read/write (404 unless `DevMode::enabled()`)
- `GET /studio/api/code/tree`, `GET|PUT|DELETE /studio/api/code/file`, `POST /studio/api/code/section` — Code mode's workspace (404 unless `DevMode::enabled()`)
- `GET|POST|PATCH|DELETE /studio/api/media…` — media library
- `GET /studio/api/assistant/engines`, `POST /studio/api/assistant/turn`, `GET|DELETE /studio/api/assistant/stream/{turn}` — the Assistant (dev mode only)

### Artisan Commands

```bash
php artisan studio:sync             # Re-read the installed site (sections + pages/data) into the editor
php artisan studio:publish          # Publish compiled assets to public/vendor/studio (--remove reverts; also: vendor:publish --tag=studio-assets)
php artisan studio:templates:sync   # Clone/pull the template repos (--list, --template=, --force)
php artisan studio:templates:import # Install a template into resources/designer + public/designer (--force replaces the installed site)
php artisan studio:dev-reset        # Fresh-install state: deletes the site, its runtime provider, and editor data (--template= to reinstall)
php artisan studio:uninstall        # Remove Studio's editor data (--keep-data); the site keeps working
```

## Gotchas

- **The files are the live site.** Editing `resources/designer` (Code mode, the Assistant, your own editor) is live at once; Studio pulls it in on the next `SiteMirror::sync()`. Never hand-edit `storage/studio/{pages,layouts,…}` (the live mirror) — it is rebuilt from the files. `storage/studio` holds nothing the site needs: a fresh deploy rebuilds it on the first `/studio` visit
- **SiteReader and SiteWriter must stay exact inverses.** Re-check after touching either, from a script that bootstraps a **throwaway** Laravel app with this package path-symlinked — never the host, whose `resources/designer` is a real site that `replace: true` deletes (`require vendor/autoload.php; $app = require bootstrap/app.php; $app->make(Kernel::class)->bootstrap();`): `SiteInstaller::install($slug, replace: true)`, hash every file in `resources/designer`, `SiteMirror::flush()` → nothing may change; then `refresh(true)` + `flush()` → still nothing. Verified on all 40 public templates in the site-templates org (2026-09-11, Laravel 13). Two writer rules that came out of it: a page's layout tag that has no `title` only gains one when an SEO title is set (the layout's own default — often just the site name — is the page's `<title>` otherwise), and a hand-written home page keeps its designer.json entry (its file is `index.blade.php`, not `{home_slug}.blade.php`). A form difference between what Studio stores and what the reader produces (e.g. `hidden: false`, resolved default variables) is fine — the writer compares values, not forms — but anything that makes an unchanged doc re-write a file is a bug
- To simulate removing Studio in the host: add `"dont-discover": ["designer/studio"]` under `extra.laravel` in the host's composer.json, `php artisan package:discover`, request the site (all pages must still serve; `/studio` 404s), then revert and re-discover
- The runtime provider is the app's file once written: to ship a runtime change, update the stub AND consider existing installs (they keep their copy; `@version` in its docblock)
- `Livewire.dispatch()` names and the postMessage protocol (`studio:*`) are shared contracts between `EditorPanel`, `home.blade.php`, `iframe.blade.php`, and `studio.js` — change them everywhere or nowhere.
- After editing `resources/css|js`, run `npm run build` (or keep `npm run dev` watching). Asset URLs come from `Support\StudioAssets::url()`: a published copy in `public/vendor/studio` wins (static file, filemtime cache buster); otherwise `AssetController` serves the package `dist/` with a per-file mtime buster. If the editor looks stale, check for a forgotten published copy (`php artisan studio:publish --remove`).
- **Render nested Blade through `Support\NestedBlade::render()`, never `Blade::render()`,** whenever the caller catches the failure (sections, lifted layout chrome, `php:`/`blade:` bindings). Laravel's `View::render()` answers any exception with `flushState()`, which wipes the component/section stacks of the view still rendering around it — the canvas iframe then 500s with "Undefined array key 0" instead of showing one broken section in place. `NestedBlade` snapshots the factory's render state and restores it before rethrowing
- **Templates must hold together at 1024–1280px.** That is the canvas width on a laptop (the screen minus the 368px of rail + sidebar), so a two-column hero that only works from 1280 looks broken in the editor even when the live site is fine on a wide monitor
- **Never take file contents from `$request->input()`/`validate()`.** Laravel's `TrimStrings` middleware strips leading and trailing whitespace from request input, which silently eats a saved file's trailing newline. `CodeController::rawContents()` reads `contents` off the raw JSON body instead; validation still guards the shape.
- **Never put a Monaco editor or model inside an Alpine store or `x-data`.** Alpine deep-proxies what it holds, and Monaco's object graphs are large and getter-heavy — doing so hangs `openFile()` silently. Code mode keeps them in the plain `studioCodeBuffers` object beside the store (`home.blade.php`); only serialisable state (tabs, active path, dirty flags) is reactive.
- The compiled asset list lives in several places that must stay in sync when files are added: `StudioAssets::FILES` (drives `studio:publish` + the provider's `studio-assets` publish tag), `AssetController::$allowedFiles` (adds MIME types), Vite's `ASSET_FILES` (`vite.config.js`), and `MONACO_FILES` in `esbuild.monaco.mjs`.
